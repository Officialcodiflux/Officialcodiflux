## Verified technology notes

Technology is only marked verified where inspected source files or the supplied GSMManagerPro specification support it. A repository name alone is not evidence of a framework. “TBD” means the stack was not confirmed, not that the project has no technology.

## Operating rules

1. Keep **portfolio status** separate from **GitHub repository activity** and **release status**.
2. A project is not “Live” merely because a repository exists; verify its public release, deployment and working user journey.
3. Record actual framework versions from manifests, not generic profile badges.
4. Record revenue, users, installs, support load and last release only when evidence is available.
5. Do not start every P1 simultaneously. Select one primary build and one revenue activity at a time.
6. Reassess priorities monthly using customer demand, revenue potential, delivery effort and support cost.
